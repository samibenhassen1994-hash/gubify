# Community Direct Asks Design

## Goal

Allow a linked current Community member to create an active Ask directly from Community Home without first posting a Chat message, while preserving Chat-derived Asks and all existing lightweight board/count behavior.

## Data model

All documents remain under `communities/{communityId}/asks/{askId}`.

Common fields are `askId`, `communityId`, `authorId`, `authorDisplayName`, `type`, `text`, `createdAt`, and `status`. `sourceMessageId` is nullable in Dart and omitted from a Direct Ask document.

- Chat Ask: `askId == sourceMessageId`; `text` equals the source message text.
- Direct Ask: `askId` is generated by Firestore `doc()`; `sourceMessageId` is absent.

There is no migration or compatibility read for the pre-beta `sourcePreview` field.

## Identity and validation

Ask text uses `AppLimits.communityMessageMaxLength` (2000), is trimmed, and must be non-empty. The author must be a linked Firebase account and current Community member.

The current display name is resolved through the existing Community identity path: a public CommunityService method reuses `_currentIdentity()`, which uses cache-backed `UserRepository.getUser()`. CommunityAskService receives this resolver through dependency injection. This avoids a second identity implementation and does not force a new network read per Ask; UserRepository may read Firestore only on cache miss, matching existing Community Chat behavior.

## API

CommunityAskService exposes `createAskFromMessage(...)` and `createDirectAsk(...)`. CommunityAskRepository mirrors those methods. Chat creation keeps its transaction and deterministic duplicate check. Direct creation obtains an auto-ID reference and writes one validated document.

## Community Home UI

The header has one enum state: `none`, `community`, `asks`, or `createAsk`. A third compact action labeled `Create` contains `Icons.add_rounded` and only toggles the Create Ask card.

`CommunityCreateAskCard` owns its text controller, selected `CommunityAskType`, submission state, and inline error. It uses a 2–4 line text field, exclusive ChoiceChips, and a local loading indicator. Invalid state cannot submit. Success resets state, closes the card, and shows `Ask created.`; failure preserves text and type.

## Rules

The `/asks/{askId}` create rule validates common fields and then branches:

- Chat Ask: `sourceMessageId` is present, equals `askId`, source message exists and belongs to the author, and `text` equals its text.
- Direct Ask: `sourceMessageId` is absent, document ID equals `askId`, and `authorDisplayName` equals the current user profile display name.

Both require a linked current member, active Community, valid type/status/text, and server timestamp. The existing safe `get` behavior for an absent deterministic Ask remains unchanged.

## Queries and indexes

Board, profile, details, and count continue querying active Asks without filtering by origin. No query changes and no new index are required.

## Scope exclusions

No replies, Best Answer, EXP, levels, attachments, editing, deletion, close flow, Private Gub changes, migration, commit, push, or deploy.
